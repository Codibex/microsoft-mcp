# v0.9.0 - Calendar writes and service-specific policy

## Highlights

- Adds `calendar_create_event` and `calendar_update_event` for delegated calendar writes, including UTC normalization, all-day events, reminders, locations, SMTP attendees and partial updates
- Adds a versioned `policy.json` with separate Outlook, Calendar and Teams sections, legacy-policy compatibility and fail-closed validation
- Adds `microsoft-mcp policy migrate --json [--write]` for previewing and atomically persisting the new policy format
- Extends `doctor --json` with policy migration status and improves setup guidance and deployment scripts
- Prevents Linux Secret Service token-cache operations from hanging and removes unsupported Teams Graph query parameters

## Upgrade notes

- Add the delegated permission `Calendars.ReadWrite` and consent again before using the calendar write tools. Calendar remains delegated-only and has no delete or move operation.
- Existing flat policy files remain compatible in memory. To persist the split policy document, run `microsoft-mcp policy migrate --json` as a preview, then `microsoft-mcp policy migrate --json --write` with administrator/root rights and restart the MCP client.
- Existing `TenantId`/`ClientId` configuration is unchanged.
